# pomo

pomo is a pomodoro focus timer for the Linux desktop. The user builds a queue of focus sessions and breaks, runs them one after another, and the app counts the focus sessions finished today. It is one PySide6 window with a glass look, runs on X11 and Wayland, and keeps its data in plain JSON files.

## Requirements

- A Linux desktop session (X11 or Wayland).
- Python 3 with the `venv` module and `pip`. Debian and Ubuntu ship the module separately as `python3-venv`; Arch includes it in `python`.
- The system libraries the PySide6 wheels link against. A normal desktop has them. On a minimal system the import fails until `libGL.so.1`, `libxkbcommon.so.0`, `libfontconfig.so.1` and `libfreetype.so.6` are present (Arch packages `libglvnd`, `libxkbcommon`, `fontconfig`). It also needs at least one font installed, or every label draws as empty boxes: any common sans font works (Arch `ttf-dejavu`, Debian and Ubuntu `fonts-dejavu-core`). The Qt X11 plugin also links the `libxcb-*` helper libraries, `libxkbcommon-x11` among them (Arch packages `xcb-util-cursor`, `xcb-util-image`, `xcb-util-keysyms`, `xcb-util-renderutil`, `xcb-util-wm`, `libxkbcommon-x11`).
- Internet access on first run, so `pip` can fetch PySide6 and Pillow.
- Optional: a sound player (`paplay`, `aplay` or `play`) for the chimes and `notify-send` for desktop notifications. Without them the timer works and stays silent.

## Run

```sh
./run.sh
```

On first run the script creates a virtual environment named `venv-<hostname>` in the checkout, installs `requirements.txt` (PySide6 and Pillow) into it, and starts the app. Later runs reuse the environment. The hostname in the name keeps one environment per machine when a checkout is shared between machines.

## Install as a desktop app

```sh
bash install.sh
```

The script builds or repairs the virtual environment, syncs the dependencies, renders the icon (`pomo.png` next to the script and a copy under `~/.local/share/icons/hicolor/256x256/apps/`), and writes `~/.local/share/applications/pomo.desktop`. Pomo then appears in the application launcher. The launcher entry points at the checkout, so the checkout must stay where it is.

## Use

The queue starts empty, and the timer cannot start until it holds a session.

1. **Add sessions.** `+  Add session` opens a popup: choose Focus, Short or Long, optionally type a name, and press Add. `PATTERN` takes counts of focus, short-break and long-break sessions and pushes them onto the queue at once (4 focus, 3 short and 1 long by default). Hovering a row shows `−` and `+` (one minute each way) and `×` (remove). Double-clicking a name or duration edits it, right-click offers Rename, Delete and Set duration, and dragging reorders rows. Clicking a pending row makes it the current session while the timer is idle. `CLEAR` empties the queue and `RESTART` marks every session pending again.
2. **Run a session.** The `▶` button, a click on the ring, or `Space` starts and pauses. `R` resets the current session and `S` skips it; a skipped session is not counted and does not chime. The gear in the header, or `Ctrl+,`, opens Settings. The shortcuts act while the main window has focus.
3. **The break.** When a session ends, the next one in the queue becomes current. With "Auto-start breaks after focus" on, the default, a break after a focus session starts by itself. "Auto-start next focus after a break" is off by default, so the next focus session waits for a start. Durations default to 45 minutes of focus, 10 of short break and 20 of long break, and Settings changes them.
4. **Chimes.** A finished focus session plays a three-note chime and a finished break plays a single note, both generated by the app, and each sends a desktop notification. "Play chimes" and "Desktop notifications" in Settings switch them off. The app has no setting for a custom sound.
5. **Stats and history.** The line under the ring reads `Today · N sessions · Xm focused` and counts completed focus sessions. Each completed focus session also appends an entry (date, name, minutes) to `history.json`. The app has no screen that lists history; the file is the record.
6. **Templates.** `TEMPLATES` opens five slots. "Save current" stores the queue in a slot, "Load" replaces the queue with the slot's sessions, and Rename and `×` manage the slot.

Settings also holds the pattern counts, the UI scale (50 to 300 percent) and the auto-start switches.

## Data

State lives in five JSON files under `$POMO_DATA_DIR`, which defaults to `~/.local/share/pomo`:

| File | Content |
|---|---|
| `stats.json` | per-day session and minute counts, plus totals |
| `history.json` | one entry per completed focus session |
| `prefs.json` | durations, pattern counts, switches, UI scale |
| `sessions.json` | the current queue |
| `templates.json` | the five template slots |

The app reads the directory once, at start. Starting it with a throwaway profile leaves the real data untouched:

```sh
POMO_DATA_DIR="$(mktemp -d)" ./run.sh
```

The queue is saved after every change. A session finished before a restart returns to the queue as pending; stats, history, preferences and templates keep what they recorded.

## Tests

The tests run headless, with no display server, using the virtual environment that `run.sh` or `install.sh` built:

```sh
"venv-$(uname -n)/bin/python" -m unittest discover tests
```
